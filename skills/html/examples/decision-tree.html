Should you add a cache?

Walk the tree before you reach for Redis. Most reads don't need it.

The decision

Is this read on a hot path? (called often, latency matters)
No
Don't cache. You're adding a moving part for a path nobody waits on. Revisit if it shows up in a trace.
Yes
Is the underlying data slow to compute or fetch?
No, it's a fast lookup
Skip it. Index the query or fix the N+1 first. A cache hides a problem you can just solve.
Yes
Can you tolerate stale reads for a bounded window?
No, must be fresh
Cache is a trap here. Optimize the source, or precompute on write instead of on read.
Yes
Cache it. Start with a short TTL, measure the hit rate, and only add invalidation once a TTL alone clearly isn't enough.
